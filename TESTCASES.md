## Регистрация

### TC-REG-01 - Успешная регистрация

**Тип:** позитивный  
**Предусловия:** username ещё не занят на стенде.  
**Шаги:**
1. Отправить POST `/api/1/register` с уникальным username и password.
2. Посмотреть ответ.
**Ожидаемый результат:** статус 201, в теле есть `id` и тот же `username`.  

### TC-REG-02 - Повторная регистрация того же username

**Тип:** негативный  
**Предусловия:** пользователь с этим username уже есть.  
**Шаги:**
1. Снова отправить POST `/api/1/register` с тем же username и password.
2. Посмотреть ответ.
**Ожидаемый результат:** ошибка, повторно пользователь не создаётся. В теле: `"username is already registered"`.  

### TC-REG-03 - Регистрация с пустым username

**Тип:** негативный / граничный  
**Предусловия:** нет.  
**Шаги:**
1. Отправить POST `/api/1/register` с `"username":""` и валидным password.
2. Посмотреть ответ.
**Ожидаемый результат:** статус 400 (или иной 4xx), пользователь не создаётся; сообщение про пустой/обязательный username.  
**Факт на стенде (2026-11-25):** 400, `"error":"invalid JSON body"` при валидном JSON (см. BUG-037).  

### TC-REG-04 - Регистрация с пустым password

**Тип:** негативный / граничный  
**Предусловия:** нет.  
**Шаги:**
1. Отправить POST `/api/1/register` с валидным username и `"password":""`.
2. Посмотреть ответ.
**Ожидаемый результат:** статус 400 (или иной 4xx), пользователь не создаётся; сообщение про пустой/обязательный password.  
**Факт на стенде (2026-11-25):** 400, `"error":"invalid JSON body"` при валидном JSON (см. BUG-037).

## Объявления

Нужен Bearer-токен. В теле создания `sellerID` должен совпадать с id пользователя из токена.

### TC-ITEM-01 - Успешное создание объявления

**Тип:** позитивный  
**Предусловия:** пользователь зарегистрирован и авторизован, есть валидный accessToken.  
**Шаги:**
1. Отправить POST `/api/1/item` с заголовком `Authorization: Bearer <token>` и телом с `sellerID`, `name`, `price`, `statistics`.
2. Посмотреть ответ.
**Ожидаемый результат:** статус 200, в теле сообщение вида `"Сохранили объявление - <uuid>"`.  

### TC-ITEM-02 - Получение объявления по id

**Тип:** позитивный  
**Предусловия:** объявление создано, известен его uuid.  
**Шаги:**
1. Отправить GET `/api/1/item/<uuid>` с Bearer-токеном.
2. Посмотреть ответ.
**Ожидаемый результат:** статус 200. Тело - массив из одного объекта с полями `id`, `name`, `price`, `sellerId`, `statistics`, `createdAt`. Значения name/price/statistics совпадают с созданными.  

### TC-ITEM-03 - Получение объявлений продавца

**Тип:** позитивный  
**Предусловия:** у продавца есть хотя бы одно объявление, известен sellerId.  
**Шаги:**
1. Отправить GET `/api/1/<sellerId>/item` с Bearer-токеном.
2. Посмотреть ответ.
**Ожидаемый результат:** статус 200, массив объявлений, среди них есть созданное (тот же id).  

### TC-ITEM-04 - Получение несуществующего объявления

**Ожидаемый результат:** статус 404, в теле сообщение что item not found.

## E2E

### TC-E2E-01 - Полный сценарий объявления

**Тип:** e2e / позитивный  
**Предусловия:** нет (данные создаются в сценарии).  
**Шаги:**
1. POST `/api/1/register` — уникальный username и password.
2. POST `/api/1/autorize` — получить Bearer-токен.
3. POST `/api/1/item` — создать объявление со своим sellerID.
4. GET `/api/1/item/<uuid>` — получить объявление.
5. GET `/api/1/statistic/<uuid>` и GET `/api/2/statistic/<uuid>` — статистика.
6. DELETE `/api/2/item/<uuid>` — удалить объявление.
7. GET `/api/1/item/<uuid>` — убедиться, что 404.
**Ожидаемый результат:** каждый шаг успешен по ожидаемым кодам; после удаления объявление не находится.
